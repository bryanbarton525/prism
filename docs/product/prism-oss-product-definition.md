# Prism OSS product definition

Prism is a self-contained, local-first specialist runtime for AI editors and MCP hosts. The parent host remains the orchestrator; Prism executes bounded specialist work with an immutable, versioned bundle of agents, skills, constitutions, references, scripts, and evals.

## Product contract

- A released binary supplies bundled specialist definitions without a repository checkout. Execution still requires the configured model runtime and any capability-specific external services or data.
- The Prism version and embedded bundle version equal the release tag.
- A deterministic SHA-256 identifies the exact embedded content.
- Development directory overrides are explicit and report separate provenance.
- Repository state is an optional, per-call workspace rather than Prism's runtime root.
- Repository plugins are constructed for and confined to the selected workspace.
- The MCP server starts without a repository and advertises the release-derived version.
- Run provenance is generated by Prism, never supplied by an MCP caller.

## Distribution

`prism install` adapts the compiled release to Codex, VS Code/GitHub Copilot, Antigravity, Claude Code, and OpenCode. It installs portable skills once, generates host-native specialist wrappers, and registers `prism mcp serve`. Project and global scopes are supported.

Installations are transactional and recorded in a Prism-owned scope manifest. Upgrades replace and remove only managed files, preserve unrelated user content, back up configuration, refuse unmanaged collisions by default, and support complete managed uninstall.

The former signed runtime registry and independently versioned bundle distribution model has been retired. A Prism GitHub release is the sole release bundle boundary.

## Agreed extension direction (not yet implemented)

User-added agents and skills will extend Prism's runtime as separately tracked runtime extensions. The release bundle remains immutable. Extensions must use names unique within their resource kind; replacing bundled agents or skills is deferred. Exporting runtime extensions into editor hosts is separate follow-on work. See [the implementation plan](../../plan.md) for the finalized implementation scope.

User-managed skill bindings apply only to user-added agents; bundled allowlists remain unchanged. The `prism install` walkthrough will assist with runtime-extension setup and skill binding in addition to its existing host-installation flow.

User-added agents may run without skills and may have an empty skill allowlist. Explicit skill attachments must be allowed; bundled agents retain their existing skill requirement.

The walkthrough will offer importing an agent or creating a uniquely named user-owned copy of a bundled agent. The copied configuration and constitution remain independent of subsequent release updates; referenced bundled skills continue to follow the installed release.

Runtime additions default to user-wide configuration. The walkthrough also offers explicit project isolation and configures the host to use that runtime configuration. Runtime scope is distinct from the existing host installation scope; isolated configurations include the release bundle but do not inherit user-wide additions.

Skills use the [Agent Skills open format](https://agentskills.io/home). Initial agent import will support native Prism definitions, Claude Code subagent Markdown, and Codex standalone custom-agent TOML, with visible compatibility reporting and guided translation into Prism's execution configuration.

Users may explicitly map or omit incompatible source features and accept the resulting behavior changes before activation. Accepted changes remain inspectable; unresolved incompatibilities prevent activation, and ordinary Prism runtime policy still applies.

Imported agents require explicit selection of a local or self-hosted offload model, including models served on the user's other machines. This preserves existing self-hosted runtime support. Source host/cloud model settings are provenance rather than implicit execution targets. Installation and translation are deterministic and make no model calls.

User-added agents will support individual MCP server selections and a general default option through the CLI and walkthrough. Effective selections govern discovery and calls; bundled agents retain existing behavior. The general default is a user-selected shared list whose changes are inherited by agents using it. Registering a server does not automatically add it to that list.

Configuration changes apply on the next direct CLI invocation or after restarting Prism's MCP server. Running tasks retain their loaded configuration; mutation output explains when a restart is needed. Live reload is deferred.

The initial release supports bounded reading of skill resources and preserves packaged scripts without introducing a general-purpose script executor. Local/GitHub sources and GitHub-backed skills.sh page installation ship first; catalog search follows separately.

The walkthrough reports host installation and runtime-extension setup as separate transactions. A failed runtime stage restores its previous state and leaves any successfully completed host installation intact with explicit retry instructions. Upgrade name conflicts preserve affected user extensions, disable them and dependent user agents with diagnostics, and offer rename/removal recovery.

The release bundle will include a Graphify-backed repository-investigation specialist, constitution, query skill, and host delegation instructions. Host instructions route suitable work through Prism; the specialist queries a workspace-bound Graphify service and verifies graph leads against current sources. The upstream executable and repository indexes remain explicit runtime prerequisites, with version-pinned setup assistance and readiness diagnostics. Listing capabilities and starting Prism do not require Graphify. Initial integration excludes automatic graph construction and semantic extraction; installation makes no inference calls.
