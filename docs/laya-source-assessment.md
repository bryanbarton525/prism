# Laya as a Prism decision-service replacement

Source assessment on 2026-09-30; local measurements belong in the separate evaluation report. No runtime settings were changed for this assessment.

## Compatibility

Laya exposes `POST /v1/systemone` with typed `answers`, including `type: noul` and a numeric `noul` probability. Its optional bearer authentication matches Prism's client. Prism's `true`/`false` criteria descriptions are valid Laya inputs. This makes an endpoint-only experiment possible. [Laya HTTP implementation](https://github.com/NandhaKishorM/laya/blob/6d942c92081fbc139e736bbd9ac0023223c29b7f/laya/serve.py), [Prism client](../internal/toolmodel/kev.go).

Prism currently accepts only `kev-latest` or `jev-latest` as decision-model names. Laya treats unrecognized names as automatic routing rather than rejecting them: those strings select English or multilingual based on the state, not Kev or a fixed checkpoint. Explicit `english`, `multilingual`, and `typed-decisions` values work at the Laya API but require a Prism change. The HF bundle name `convaiinnovations/laya` also means automatic routing at the HTTP surface. `LAYA_MODELS` controls preloading, not which checkpoints requests may load. [HTTP model resolution and router construction](https://github.com/NandhaKishorM/laya/blob/6d942c92081fbc139e736bbd9ac0023223c29b7f/laya/serve.py), [checkpoint aliases](https://github.com/NandhaKishorM/laya/blob/6d942c92081fbc139e736bbd9ac0023223c29b7f/laya/router.py).

Prism sends one independent yes/no question per tool, up to 20 tools, and enforces a five-second HTTP deadline. Laya allows 64 questions and processes them together; its 100-option choice limit is a different constraint from Prism's independent binary scoring. Verify the full 20-question request on this CPU, since a timeout disables the current Prism client until restart. [Prism client](../internal/toolmodel/kev.go), [Laya HTTP limits](https://github.com/NandhaKishorM/laya/blob/6d942c92081fbc139e736bbd9ac0023223c29b7f/laya/serve.py).

## Accuracy concerns specific to tool scoring

Laya's own documentation reports that default `false`/`true` option labels can dominate English `noul` answers. Current code supports `labels: {"false": "B", "true": "A"}` while retaining the returned probability's meaning, P(true). Prism does not currently send this field. Compare unchanged Prism questions against neutral labels; validate both rather than assuming the override fixes every example. Criteria must retain `true`/`false` keys. [Typed-question documentation and limitations](https://github.com/NandhaKishorM/laya/blob/6d942c92081fbc139e736bbd9ac0023223c29b7f/README.md), [Agent validation and response construction](https://github.com/NandhaKishorM/laya/blob/6d942c92081fbc139e736bbd9ac0023223c29b7f/laya/agent.py).

The model family includes a 421M English checkpoint, 322M multilingual checkpoint, and a separate 421M typed-decisions checkpoint. The model card's 0.766 typed-decision accuracy belongs to the fine-tuned checkpoint; base English is 0.362 versus a 0.461 majority baseline. Published Laya versus Jev results are not a controlled local comparison: Jev measurements came from other authors with different prompts and sample sizes. The quoted approximately 33 ms is T4 GPU latency, not a promise for this CPU or 20-tool batch. [Model card](https://huggingface.co/convaiinnovations/laya), [benchmark methodology](https://github.com/NandhaKishorM/laya/blob/6d942c92081fbc139e736bbd9ac0023223c29b7f/BENCHMARKS.md).

Default English context is only 512 tokens, with 192 reserved for the question head; multilingual defaults to 1,024 with a 256-token head. Long tasks and verbose tool descriptions can truncate. Current HTTP code accepts per-request `max_len` and `head_max_len`, capped at 8,192 by default; Prism sends neither. Calibration should be evaluated locally; the training objective does not establish reliable probabilities for unseen Prism tool-selection workloads. [Token budgets and calibration limitations](https://github.com/NandhaKishorM/laya/blob/6d942c92081fbc139e736bbd9ac0023223c29b7f/README.md), [HTTP controls](https://github.com/NandhaKishorM/laya/blob/6d942c92081fbc139e736bbd9ac0023223c29b7f/laya/serve.py).

## CPU, ONNX, and reproducibility

The ordinary server supports `LAYA_DEVICE=cpu`, `LAYA_HOST=127.0.0.1`, `LAYA_PORT`, and `LAYA_THREADS`. Restricting threads to physical cores is the project's recommendation. Default startup preloads all three models; explicitly preloading only English avoids that startup memory cost for an English evaluation. Verify `/health` because requested GPU devices may fall back to CPU. [Server configuration](https://github.com/NandhaKishorM/laya/blob/6d942c92081fbc139e736bbd9ac0023223c29b7f/laya/serve.py).

ONNX is supported through `ONNXAgent`, not a built-in `laya-serve` environment toggle. `create_app(router=...)` and `Router.attach(...)` provide a custom integration path. No ONNX files were present in the HF bundle listing at assessment time, so an export is required. `scripts/export_onnx.py --model LOCAL_PINNED_MODEL --output laya.onnx --quantize` exports FP32 and an INT8 dynamic per-channel MatMul variant; exporting requires PyTorch. Measure parity and latency after quantization. [Export script](https://github.com/NandhaKishorM/laya/blob/6d942c92081fbc139e736bbd9ac0023223c29b7f/scripts/export_onnx.py), [ONNX runtime](https://github.com/NandhaKishorM/laya/blob/6d942c92081fbc139e736bbd9ac0023223c29b7f/laya/onnx_agent.py), [HF artifact inventory](https://huggingface.co/api/models/convaiinnovations/laya).

Record separate package, source, and checkpoint pins. At assessment time PyPI reported `laya==0.3.22` with Apache-2.0 metadata, GitHub main resolved to `6d942c92081fbc139e736bbd9ac0023223c29b7f`, and the HF bundle resolved to `55cf4c4ebb4ebe31b2550e8bdf3bd21b99753851`. The HF card's runtime changelog still described 0.3.20, so do not infer package behavior from that version label. Current code supports checkpoint revisions and artifact SHA-256 verification; set those explicitly for a managed install. [PyPI metadata](https://pypi.org/pypi/laya/json), [GitHub source pin](https://github.com/NandhaKishorM/laya/tree/6d942c92081fbc139e736bbd9ac0023223c29b7f), [HF checkpoint pin](https://huggingface.co/convaiinnovations/laya/tree/55cf4c4ebb4ebe31b2550e8bdf3bd21b99753851), [revision verification](https://github.com/NandhaKishorM/laya/blob/6d942c92081fbc139e736bbd9ac0023223c29b7f/laya/revisions.py).

## Decision gate

Evaluate unchanged Prism requests first, then neutral labels and explicitly selected checkpoints. Compare ranked tool relevance, irrelevant-task false positives, long-task truncation, warm 2/20-tool latency, and cold startup memory against the already installed Kev and ONNX shortlist. A successful HTTP response establishes compatibility; adopting Laya needs useful ranking and reliable latency on this workload.
